MADE FOR DEVELOPERS

Getting started

A simple, honest workflow to demonstrate real access-control verification.

01

Start the grocery lab

Open a terminal at the project root and run the synthetic shop on port 4200.

npm.cmd run lab:start
Open grocery storefront
02

Start the verifier

Open a second terminal from the project root. The dashboard and API share port 4100.

npm.cmd install
npm.cmd run dev
03

Register reviewed suites

Select Security promises → Load demo suites. This registers the two bundled, approved JSON contracts using the existing backend API.

04

Run and inspect actual evidence

Select a suite, review its permission rules, explicitly approve disposable synthetic updates, and run. Findings and history come from the verifier's saved results.

What this demo proves

Tests observe actual HTTP responses, verified customer identity, protected synthetic markers, and before/after state changes.

Real limitations

  • Two local training adapters are supported: Sprout & Stone grocery and CareBridge fictional hospital. Other links are planning-only.
  • The intentionally insecure grocery lab must never be publicly deployed.
  • G11/G12 fault-injection cases are not integrated into this archive.
  • Write tests need explicit approval and trusted reset.
  • Automated code repair or deployment is not included.
